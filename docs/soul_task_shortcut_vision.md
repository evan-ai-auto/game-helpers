# 命魂任务快捷图标集合视觉检测

当前命魂任务诊断流程需要先确认左上角快捷图标集合是否展开。

## 真实素材语义

- `shortcut_toggle_right_light.png`：右向箭头，语义为折叠态。
- `shortcut_toggle_right_gray.png`：右向箭头，语义为折叠态。
- `shortcut_toggle_left_light.png`：左向箭头，语义为展开态。
- 图4对应的命魂任务目标图标暂继续使用仓库现有 `soul_task_claimed_icon.json`；新的图4素材尚未成功上传，本次不替换该资产。

## 检测策略

800×600 基线下的快捷图标集合箭头 ROI 使用 `[0, 80, 40, 128]`。

之所以把 ROI 左边界设为 `x=0`：真实素材显示箭头贴近客户区最左边缘。此前 `[8, 82, 52, 128]` 会裁掉真实箭头的一部分，导致视觉匹配可能在箭头右侧背景中找到较高分的伪匹配，进而计算出错误的点击位置。

模板使用透明背景，匹配时忽略透明像素，避免游戏场景背景影响结果。

语义映射：

```text
RIGHT_LIGHT / RIGHT_GRAY -> COLLAPSED
LEFT_LIGHT               -> EXPANDED
```

折叠态点击位置由视觉匹配结果计算箭头中心，而不是使用原先的固定 `(25, 153)` 坐标。点击后重新截图并要求状态变为 `EXPANDED`。

## 本次真机失败后的修正

用户 Windows 真机第二角色运行时仍出现：

```text
点击快捷图标集合开关后仍检测为折叠状态
```

离线复核当前真实截图后发现，旧 ROI 从 `x=8` 开始，实际箭头位于客户区左边缘，因此存在“真实箭头被裁剪 + 右侧背景伪匹配”的问题。

本次修正：

1. 增加 `shortcut_panel_vision.py`，将快捷面板视觉 ROI 固定为左边缘可见区域。
2. 命魂流程改用该检测器。
3. 点击后失败时保存失败截图，并在错误信息中输出点击坐标、匹配模板和二次检测证据。
4. `vision_regions.json` 同步更新为 `[0, 80, 40, 128]`。

新的图4目标素材到位后，应单独更新目标图标资产并重新做回归验证。
