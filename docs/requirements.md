# 产品需求

Agent 实现功能时以本文为准。

## 目标

在 **纯后台** 下，对已授权的游戏窗口做检测与自动化：选中登录角色后，按已定义任务流程自动执行。

## 当前基线

- 统一子窗口分辨率 **800×600** 实现与验收完整链路。
- **多分辨率**（大小窗切换、宿主重排等）后续单独优化，见 [backlog.md](backlog.md)。

## 能力清单

1. **窗口与角色**：检测游戏窗口；识别角色登录信息（是否登录、角色名、分辨率等）。
2. **界面自动化**：在游戏界面上完成点击、开关面板等操作。
3. **纯后台**：不把游戏窗口拉到 Windows 最前；不抢焦点做 Ctrl+Tab。
4. **多子窗口**：支持多个 WSGAME 子窗口 / 账号视图之间切换。
5. **界面状态**：检测当前 UI 状态（如任务是否已领取、道具栏开/关等）。
6. **资产可维护**：图标、状态检测等模板资产支持后续增删改（人工维护方式见 [maintain.md](maintain.md)）。
7. **任务流程**：用已验证资产定义流程；对「已选角色」执行「已选流程」。

## 硬性约束

- 默认纯后台；除非需求明确允许，否则禁止前台激活游戏。
- 只做授权场景的自动化与测试，不做作弊 / 破解类能力。
- 资产与流程要可单独维护，避免把模板硬编码进逻辑里。
- 单文件大小不要超过 github 仓库限制,避免文件读取写入内容被截断

## 主链路（实现时对齐）

自动化通用流程
```
发现窗口 -> 识别角色 -> 选择任务类型 -> 任务领取状态检测 -> 任务执行 -> 任务执行结果检测 -> 异常终止并友好提示
```

命魂任务流程（当前已打通的最小闭环）
```
发现窗口 → 选择已登录角色 → 选择任务类型[命魂任务]
  → 后台同步 → 检测命魂任务领取状态 → 友好结果/异常提示
```
（本阶段只做领取状态检测，不自动去 NPC 领取。）

已验证能力点的复用入口见 [capabilities.md](capabilities.md)。
